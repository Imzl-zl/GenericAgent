核心安全边界

允许的能力

  • 在本会话工作区读写文件
  • 执行 Shell、Python 和文档解析工具
  • 通过受控 LLM Proxy 调模型
  • 通过显式平台工具访问获批外部能力

明确禁止

  • 读取其他用户、团队或宿主机文件
  • 读取 bot token、模型 Key、数据库凭证
  • 访问 Docker/Podman socket
  • 任意外网、提权、无限进程和无限资源

三种路线对比

A

单进程多线程

部署最省事；但 Shell/Python 与控制面同 OS 用户，路径白名单和字符串黑名单可绕过，无法满足多租户安全。

B

单机隔离 Worker（推荐）

一台服务器即可。rootless Podman/Docker 管理短生命周期 worker；保留 Shell/Python，且具备可验证的租户隔离。以后可平滑迁移到 Kubernetes。

C

Kubernetes

扩缩容和调度最好；但 10–20 人试运行阶段运维成本过高，暂时不值得。

建议选 B。它不是“每个用户永久跑一个容器”，而是“每个活跃个人/团队会话按需启动一个 worker；空闲保存后销毁”。
